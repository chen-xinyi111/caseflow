# CaseFlow 使用演示

当前交付的是供人工执行的检查清单，不是自动化测试代码。

## 核对依据与数值

在用例详情展开“依据检查”，逐项查看前置、输入、步骤和预期的说明；“自动复核未发现疑点”不等于审核通过。现有用例可先保存草稿，再点击“检查已保存内容”；需先在需求页授权资料范围。有疑点、未完成或修改后失效的检查，需要重新复核或明确人工确认。

需要固定数值计算时，在需求页展开“数值规则”，关联已确认需求、填写门槛与抵扣金额或闭区间，再核对确认。生成时选齐关联需求，程序生成适用场景的规范输入及预期。详情保留计算前草稿。现有人工编辑不会被自动改写。

## 需求到交付

1. 打开项目首页，选择会议室预约示例，或新建项目并导入data/caseflow-examples中的资料。
2. 核对解析正文、选择本轮资料，确认时长规则。示例里的预置清单由人工编写，真实资料需要整理需求。
3. 配好模型并明确允许处理后，选择确认需求，生成用例。检查依据与未确定预期。
4. 编辑一条用例并审核，导出Excel，核对输入、步骤、预期和审核状态。
5. 在执行结果记录“未执行”。只有在实际业务系统中测试之后，才填写通过或失败。

## 变更维护

1. 上传reservation-update.md，并在“更新已有资料”中关联原预约说明。
2. 仅选择更新资料，整理需求，在变更页确认时长上限的修改。
3. 核对原用例已经转为待复审，内容及历史仍然保留。
4. 确认新需求，再生成修改草稿。检查原用例替换关系，编辑建议后应用到原用例，再次审核。
5. 查看稳定编号、修订历史与旧执行记录。旧修订的结果不能证明新修订已经通过。

文件共享和活动报名也可独立体验。生成只是辅助设计，用户仍需核对需求完整性和步骤可执行性。

核对长资料发现漏项时，展开“补充遗漏需求”，选择资料与页码、粘贴连续原文并写明需求，保存后再确认。每批生成最多3条，更多场景可选择对应规则继续设计。添加更新资料后核对默认范围：当前资料默认选择，历史资料保留供显式查阅。
