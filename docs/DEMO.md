# CaseFlow 操作步骤

从空白项目开始，使用自己的需求资料。平台不预填业务场景，输出是供人工执行的检查步骤与预期，不是自动运行的测试代码。

## 需求到交付

1. 首页输入项目名称，点击“创建并开始”。
2. 粘贴需求文字，或上传Word、文本PDF、Markdown或TXT。点击“保存并继续”，核对解析正文。
3. 选择本次资料并允许模型处理，点击“读取需求”。完成后进入规则核对；顶部始终显示当前进度与下一步。
4. 对照原文确认规则，不清楚的条件保留待确认。选择已确认规则，允许使用对应资料，点击“生成检查清单”。
5. 在“检查清单”核对步骤、输入、预期与依据。可在详情中选择资料，点击“检查已保存内容”，完成后直接显示结果；自动判断可能漏判。
6. 编辑并填写审核说明，审核后导出Excel或Markdown。实际操作业务系统后，再填写执行结果；未执行时不填通过。

## 维护需求更新

1. 在需求页展开“添加或更新需求资料”，选择要更新的原资料，导入新内容并读取。
2. “需求更新”页一次显示一项候选。核对新旧内容，选择对应原规则，保存修改；仅换说法时可保留原内容。
3. 在同一页确认修改后的规则，继续处理剩余候选。候选关联可能错误，不批量自动接受。
4. 查看同页列出的待复审检查项。可人工维护或按确认规则生成修改建议，接受后重新审核；保留原编号、旧修订和人工修改。
5. 导出当前清单，旧执行结果仍属于旧修订，不能当作当前版本通过。

## 按需使用的选项

资料名称与用途、检索选项、数值规则、执行记录和处理历史默认折叠。数值规则只支持人工确认的固定抵扣与含上下限范围，不代替整个业务判断。项目可归档和恢复，内容与历史保留。
