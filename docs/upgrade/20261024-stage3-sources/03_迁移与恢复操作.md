## 备份与显式迁移

正式升级前安排一致备份，确认没有活动任务、未知外部请求和未保存编辑。现有`./scripts/local/Backup.ps1 -VerifyRestore`会停止并恢复应用服务，**不能在用户工作期间顺手执行**。按现有部署流程安排停机，保存备份位置和恢复验证结果；本轮未运行此脚本。既有备份工具用pg_dump自定义格式保存全库，指纹检查动态枚举表并比较to_jsonb文本（含bytea表示）；新表备份/恢复实测仍待完成。

先在独立恢复库验证备份可读，再部署兼容版应用。新侧表DDL位于caseflow/schema.sql，由既有初始化流程创建；未初始化侧表前，不执行迁移CLI。不要为了填表重新导入旧资料或调用模型。

```powershell
# 默认dry-run：仅统计尚无侧表的旧资料，不写入业务或版本行
./.venv/Scripts/python.exe scripts/migrate_caseflow_documents.py
# 可限制单个项目：替换为已核对的项目UUID
./.venv/Scripts/python.exe scripts/migrate_caseflow_documents.py --project <项目UUID>
# 完成一致备份、独立恢复和隔离验证后才显式追加旧文本侧表
./.venv/Scripts/python.exe scripts/migrate_caseflow_documents.py --project <项目UUID> --apply
```

dry-run会使用项目行锁读取，不写入；仍应在空闲时执行。apply只复制已保存pages，source_kind=legacy、format=legacy_text、原件与摘要为空。重复apply应报告0份待补；不得改变项目revision、R/T编号、正文、人工审核、执行记录、任务或设置。新文件若原件侧表丢失应报错，不降级为旧文本以掩盖损坏。
