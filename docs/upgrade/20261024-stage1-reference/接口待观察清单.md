## 未来补证方式【建议；本轮未执行】

取得可访问目标或抓包后，先核对实际 REA 版本及工具能力，再在新的补证记录中保存目标、观察窗口、工具版本、证据 ID、操作前后截图和真实请求。保留这份初始“未观察”记录，不覆盖成仿佛本轮已实测。

观察单次操作时，关联操作前状态、操作时间、真实请求、响应、任务／事件、操作后画面和刷新结果。网络成功不能独自证明业务保存成功；仅看到后续页面也不能证明它来自刚才那次请求。

如果操作未产生捕获请求，应记录“当前窗口未捕获”，而非宣布没有接口；缓存、连接时机和本地操作均可能影响观察。静态脚本发现的字符串另记候选线索，不填入“实际请求路径”。

至少覆盖一次失败／部分结果、重复提交、编辑冲突、刷新、旧引文、断线和任务恢复。会消耗模型额度的操作需先具备用户明确调用范围；破坏性行为使用可丢弃测试副本。抓包分享前去除凭据、Cookie 和私人正文。

接口补证不是第二阶段源码设计的阻塞前提：CaseFlow 的增量接口应依据自身代码、已确认目标和版本保护要求设计，无须复刻未知参考站接口。
