# 第五阶段：主流程与实现

日期：2026-10-25。源码已证与本轮工程/页面观察分别记录在验证文档。本轮只完成原提示词第5段，不进入回归计划、模拟业务、问题登记或复测功能。

## 用户主流程

1. **资料与知识**：导入需求A、公共资料B，打开解析正文核对。填写测试目标，明确选择授权版本，准备依据。覆盖记录表示所选段处理情况，不保证语义找全；规则草稿仍标draft，数值计算规则另行明确确认。
2. **测试点评审**：从准备包提取测试点，核对意图、场景组、规则、适用条件、位置校验与模型意见。处理相关问题，人工通过当前修订。普通规则无需重复逐条确认；严格流程保留原约束。
3. **详细用例**：明确选择一个或多个当前已通过测试点，允许发送采用范围。后台每点一个叶任务，每叶最多3条；完成仅表示结构/位置合格草稿已保存，不表示人工审核或业务执行通过。任务中心展示完成、失败、待处理、首次失败及继续操作。不同点同标题可以分别保存。
4. **审核与交付**：按测试点筛选并打开用例。核对前置、数据、步骤、预期，查看冻结的TP/R修订、公共条件、明确回答和原文版本。点击精确证据打开对应原文并高亮。编辑内容后模型意见失效；不可用/有疑点时逐例核对四项并写带依据的说明，缺失业务规则或明确冲突仍需先处理。审核通过只代表用例设计。
5. **导出/记录**：Excel和Markdown带完整追溯。真正执行业务后可录入结果；只构造测试数据时保持“未执行”。本机定位链接需服务运行，规范文本位置不冒充原件版式坐标。

## 变更闭环

需求A v1时长30至180（含上下限），v2只改为30至120。保存新版不会改旧原件、旧证据和用例正文；相关TP/T转待复审，旧执行快照不再是当前修订结果。无关来源的点和用例保持有效。

重新准备新版本，人工接受规则变化，适用数值规则仍显式确认；将原TP绑定新依据并重新人工通过。随后有两种明确操作：打开原T绑定同一TP的当前修订并保存草稿，或重新展开由模型提出针对旧T的建议。绑定变化也增加T修订。建议保存时冻结目标T编号、修订和内容指纹；后来的人工编辑会拒绝过期建议，应用成功保留原T编号并产生新修订，建议自身保留已应用记录。再次设计审核后才可作为当前执行对象。

150分钟在v1符合时长范围、在v2不符合。程序生成的范围结论不推出整体预约一定成功。历史执行的v1快照仍可查看；旧证据链接仍打开v1。

## 技术落点与约束

| 部分 | 入口与行为 |
|---|---|
| 统一资格 | `case_trace.require_point/reasons/approve`贯穿创建、输入、校验、保存、复核、编辑和建议应用，检查approved、当前依赖和批准指纹 |
| 有界生成 | `case_expansion`使用LangGraph，最多5次设计/8次工具/1次格式修正/1次复核；每点最多3条，完整上下文超32KiB要求拆点，不静默删公共条件 |
| 相同采用范围 | 注入本TP全部已选精确证据、包项、R状态、明确回答、数值规则；额外检索只作未采用线索，不自动纳入来源 |
| 冻结关联 | 每T一个TP及revision/fingerprint，包与包项、evidence_ids、R bindings、source_versions及trace_snapshot；新旧复核协议区分 |
| 原子事务 | 复用groups.atomic_commit：业务、任务完成、事件、叶结果与父组expected_revision同事务；generation_key防重，不按标题跨点去重 |
| 故障与预算 | 已知结构失败保留首次记录并可继续其他点；预算停止保存有效草稿后停组；未知响应/用量禁止后续派发、继续或换request_id重发；不自动增额度 |
| 人工并发 | 单例/批量均要求case_revision和binding_fingerprint；批量任一非法整批回滚并返回逐条原因；指纹协议字段不经文本脱敏 |
| 追溯与导出 | 项目内trace接口；复用不可变文档和证据阅读器；链接由服务端既存证据生成，导出含TP/R/公共条件/版本/位置，XLSX继续inlineStr |

复核失败只降低为明确未复核草稿，不自动批准。明确缺规则或冲突产生关联问题并使TP需复审，不允许全局确认绕过。人工编辑数值输入/预期后需明确重新计算再核对，也可明确移除计算，不能悄悄改写人的预期。

## 兼容与升级

不新增业务表；cf_task_groups.kind约束增量允许expand_cases，叶任务复用cf_tasks。旧T没有点协议时只读派生legacy_direct，保留原R/引用，测试点导出列为空，不回填虚构的TP或审批。旧strict生成、审核、执行、归档保留。新standard不能使用旧generate绕过TP。

任务签名加入新协议版本，旧处理中任务不能盲目沿用新处理规则。prepare再次处理相同doc/text/精确证据时复用原规则，不覆盖人工编辑，也不把相同文字但不同版本证据合并。启动前需按部署说明备份并确认无活跃任务/父组。隔离库已检验的迁移/恢复不等于用户业务库已升级；本轮未连接用户数据库。
