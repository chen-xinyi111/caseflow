# 兼容、实施顺序与验收设计

日期：2026-10-24。本文所有工程／页面／模型验收项都为**待实施、未执行**；不能将其写作本轮通过记录。第二阶段只核对源码并交付设计。

## 兼容与增量迁移

| 对象 | 迁移／读取决定 | 禁止行为 |
|---|---|---|
| 旧项目 | workflow_mode 缺失按 strict；public 只提供默认值。新增项目第4段才默认 standard | 自动批量改为标准、补写人工批准 |
| 旧资料 | 保留 document_id、previous_id、pages 和 sha256；幂等侧表迁移复制现存文本为 legacy_text 快照，bytes/hash为空，标记原件缺失 | 根据文件名或现有 KB TXT 伪造 PDF/DOCX 原件，重新导入或重新模型提取用户数据 |
| 旧引用 | 原 page/quote 保留，候选精确匹配；明确选定后追加 evidence，不改历史原文 | 重复文字默认取第一处，模糊位置显示校验成功 |
| 旧规则与回答 | R 编号、修订、origin、status、问题和答案原样保留；新的问题映射仅追加 | 将模型草稿批量 confirmed、覆盖人工文字或猜语义去重 |
| 旧用例 | 缺 point 字段显示 legacy_direct；原 requirement_ids/revisions 不变 | 自动合成 TP、伪造审核，因缺新字段丢弃旧用例 |
| 历史执行／导出 | 保留旧完整快照和当时正文；新 public current 加入新关系，仅对新链路适用 | 将旧执行结果标成新版通过或静默重算历史预期 |
| 旧任务与设置 | 保留原 kind、结果、请求账本和配置；新协议签名变化使未完成旧任务不能按新规则自动恢复 | 删除未知调用、变更模型、增预算、沿用旧响应冒充新协议 |
| 检索索引 | 旧索引只作旧链路参考；新精确映射显式构建／选择，完全匹配才复用 | 自动全库重建、用全局 active index、上传后自动向量化 |

第三阶段建立版本／证据侧表的 DDL 可放入现有初始化的幂等 schema；历史侧表填充提供单独 dry-run 和执行入口，不嵌入 GET。仅复制已保存规范文本及原身份，不改写旧 JSON 业务正文或历史。无法可靠判断原格式的统一 legacy_text；用户后补原件应成为新版本，不覆盖旧快照。

迁移版本和完成标识记录在新增元数据，重复执行不新建相同侧表行。保存新文件时解析失败、项目修订冲突或侧表写入失败应整事务回滚，不留下“列表成功但原件缺失”的半成品。迁移不调用模型，不触发索引。

正式迁移前对当前应用做一致备份与独立恢复验证；现有 `scripts/local/Backup.ps1 -VerifyRestore` 有停启服务副作用，只能在实施阶段安排。全库备份动态枚举表，可覆盖新 bytea；第四阶段须扩展活跃任务检查，纳入新任务组 queued/running，防止批次间隙误判空闲。**本轮没有执行备份、停启或数据库初始化。**

回退优先关闭新入口／停止新调度，保留兼容版代码和新增表继续读取旧资产。若需要旧二进制，用迁移前备份恢复到独立数据库验证后切换；不在已有新数据的库上删除新表或逆向改写 JSON，原库和升级后资产完整保留。冻结未完成组，未知模型响应不自动重发。

## 各阶段实施顺序与边界

| 阶段 | 必做顺序 | 交付时必须说明 |
|---|---|---|
| 第3段 | 新原件／快照侧表及旧文本兼容 → 精确证据／项目读接口 → hash 定位阅读页 → 索引的版本／位置映射与状态 | 原件、规范文本和位置的真实含义；旧资料限制；以下 S3 项实际结果及未验范围。此段不提前实现测试点或模型准备 |
| 第4段 | 项目模式与统一依赖资格 → 任务组基础和原子提交 → 依据准备与完整处理记录 → TP资源／问题映射／三类检查 → 单项与批量人工评审 | 普通 R 仍为草稿，严格与数值门槛保留；以下 S4 结果。生成详细用例仍属于第5段，不提前宣称主流程已贯通 |
| 第5段 | 从通过点小批次展开 → 同源生成／复核和人工用例审核 → 点与用例建议／变更传播 → 导出追溯 → 预约变更闭环 | 新旧用例关系、恢复与历史、以下 S5 结果；未做模型试用时明确保留质量未知 |

建议按职责在 `src/opslens/caseflow/` 新增 documents/evidence、basis/points、groups 等局部模块，现有 store/agent/api 只接入必要部分；前端从 CaseFlow 主组件拆出资料阅读与测试点评审子组件。继续使用现有 FastAPI、Pydantic、Vue、LangGraph、PostgreSQL 与 RAG，不引入新平台或新模型服务。

每阶段同步真实 OpenAPI 导出和前端类型（实施时才执行生成命令），不把第二阶段草案直接写入当前 openapi.json。生成类型前核对脚本副作用；不以手工改生成文件代替接口实现。

## 第三阶段验收矩阵（未执行）

| ID | 场景 | 通过条件／证据类型 |
|---|---|---|
| S3-01 | PDF、DOCX、MD、TXT、粘贴保存 | 原 bytes 与 SHA256 一致；规范文本／签名可查；PDF 是真实页，其他为段落；工程+页面 |
| S3-02 | 原有 legacy 资料 | 原 JSON 正文／历史不变、原件404且提示明确；旧引用仍能看文本；工程+页面 |
| S3-03 | 精确引文 | 版本／unit／start/end／文字／哈希一致才高亮，错误字段或 bool 偏移拒绝；工程 |
| S3-04 | 重复文字 | 同页／跨页多处相同引文必须明确区分；复制和刷新仍指向所选位置；工程+页面 |
| S3-05 | 跨页与多段 | 多片段分别高亮，未引用的中间内容不冒充连续原文；工程+页面 |
| S3-06 | Unicode 与清理 | emoji、非 BMP 字符、组合字符、CRLF、脱敏变化不导致前后端偏移错位；规范与原件区别清楚；工程 |
| S3-07 | URL 打开与归档 | 新标签／刷新／浏览器后退打开正确项目版本；归档可只读；无效 ID 不回落其他项目；页面 |
| S3-08 | 项目隔离 | A项目请求B的版本、证据、原件返回404；新检索只含允许版本，不直接暴露全局KB；工程 |
| S3-09 | 文档更新 | 原 ID/链接保持有效，新版新ID；仅更新解析规则也不原地改旧快照；工程+页面 |
| S3-10 | 解析边界与失败 | 原有5MiB、100000字符、PDF200页、空白／图像／宏／加密限制与提醒保留；无半成品资产；工程 |
| S3-11 | 索引绑定与状态 | 逐页chunk映射准确，版本／参数改变标旧索引过期；关键词不需Embedding，新建索引需明确操作；工程+页面 |
| S3-12 | 迁移与恢复 | dry-run无写入；执行两次一致；侧表迁移不改旧正文；含bytea的新备份可独立恢复校验；隔离环境 |

S3-01/S3-09 另覆盖两份原件不同但清理后正文相同的文件：不得错误复用成同一原件；兼容 pages 必须与同版本规范快照一致。

## 固定预约资料与独立检查清单（未来测试夹具）

以下是明确构造的验收资料，不是现存用户业务事实，本轮未写入业务资料库。

```text
需求A v1：
员工可预约空闲会议室。
预约时长为30至180分钟，包含上下限。
管理员可以查看全部预约，普通员工只能查看自己的预约。

需求A v2：
只把上文“30至180分钟”改为“30至120分钟”，其他文字不变。

公共资料B：
预约时长限制同时适用于员工和管理员。
本资料不规定失败提示文案、弹窗颜色或页面位置。
```

检查清单应在看模型输出前固定：

- 最短时长29/30/31；v1最大边界179/180/181；v2最大边界119/120/121；结论限定为时长规则符合／不符合，不写整体预约必成功。
- 150分钟在v1符合时长范围、v2不符合；普通员工与管理员均使用同一时长限制，公共资料B被纳入生成和复核。
- 权限点分别检查可见范围；不得把未规定的失败文案／红色弹窗当确定预期。额外构造一个权限待澄清问题，只阻塞相关权限点，不阻塞时长点。
- v1/v2证据链接、同一文档的重复文字及两个项目隔离单独核对；人工编辑的备注和正文保留。
- 新生成是草稿，人工设计审核是审批；没有对接业务执行时，执行记录保持“未执行”。

这些数值是测试数据，不能计作模型真实表现或实验结果。真实模型试用另需明确调用范围，保留首次失败、漏点、无依据要求、重复与人工修改；受控响应只证明工程机制。

## 实施时的检查入口

优先扩展现有 `test_caseflow_core.py`、`test_caseflow_database.py`、`test_caseflow_grounding.py`，复用受控 Provider；增加文档／测试点／组任务的针对性测试。数据库使用隔离 schema，不连接生产业务进行夹具改写。保留 durability 与空库启动回归，确认不会启用旧 worker 或模型。

按阶段执行定向测试及前端逻辑／类型／构建，接口变更时重新导出 OpenAPI 并同步类型。参考现有部署文档命令，最终变更量足够时运行完整后端回归（排除依赖旧实验实例的 test_integration.py）。本轮没有执行上述业务测试、构建、导出类型或迁移。
