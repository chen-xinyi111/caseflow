# CaseFlow 真实样本检查

检查日期：2026-10-18。只发送自编业务资料，使用用户确认的免费模型qwen3.8-max-0902。固定输入和核对清单保存在data/caseflow-evaluation/samples.json。原始请求、响应、项目快照和账户额度证据仅保留本机；下表是人工定性核对，不是准确率或统计显著性结论。

## 检查方法

先固定明确规则、未知条件和不能自行补造的结论，再查看输出。区分全文是否送达、模型是否提取、引用是否存在、预期是否由资料支持，以及用例是否可执行。示例活动ID、测试时间和余额是测试数据，不因出现具体数值就判为虚构业务规则；把这些数据当成产品强制规则才属于错误。

本轮没有用同一批结果改提示后重新声称留出成绩。首轮失败保留；缩小默认批量后的文件权限和积分结果记为复查，另增未参与此前调整的图书借阅资料。每组只做少量调用，不推断总体成功率。

## 与直接聊天的对照

直接聊天使用同一模型、2048最大输出和同一份原始业务资料，前四组最多8条，图书借阅最多3条；平台首轮也是最多8条，调整后最多3条并按需求分批。字段约束、工具上下文和人工作业不同，因此不把条数差异当成公平质量排名。

直接聊天分别返回文件权限8条、报名8条、积分8条、退款冲突6条、借阅3条，均可解析。它也能提出边界和待澄清项，初次生成在这些小资料上并不需要专门平台。借阅对照中把“非会员或已达上限”合到一条，单一输入不能隔离两个原因；部分正向用例把满足部分规则推成整体成功。这些也需人工拆分或限定预期。

平台首轮文件权限和积分生成失败，表明额外结构、引用和工具上下文有开销。小批量改善了本次输出交付，但没有证明语义质量胜过聊天。平台的可观察价值是后续资产管理：来源校验、规则确认、审核、稳定编号、变更对照、历史结果和导出；这些在聊天对照中仍需人工另建台账。本次没有测量团队使用耗时或收益。

## 真实工具与检索范围

本批生成任务的实际工具事件为read_requirements、existing_cases、read_document各8次；没有search_documents事件。不能说这些生成每次都经过RAG。另行通过同一个项目工具完成关键词检索，授权范围只含更新资料，命中1至60字符规则，未混入历史1至80资料。此前已完成真实Embedding及重排的独立记录，仍与Agent选不选择检索分开说明。

## 变更与交付

文件名上限从80改为60后，相关3条旧用例转为待复审，权限类用例与人工修改保留。真实Agent提出1条替换建议及2条新增草稿，未把全部旧边界自动映射。页面核对并修正替换建议后沿用T004；T005、T006由人工按60、61字符更新，重复新增草稿被驳回，原编号保留。

旧81字符批次绑定旧T006修订，新61字符批次绑定新修订；二者均记“未执行”，没有连接外部文件系统或伪造业务测试通过。Excel和Markdown按保存后的设计导出，字段与审核说明一致；历史、已应用建议和驳回状态保留。

## 结论边界

当前适合本机单用户的需求与测试资产工作台。已完成跨业务小样本检查和可恢复的人工维护闭环；模型仍会漏项、增加未定义前提或给出部分建议。缺少多人权限、OCR和自动测试执行。本次不提供准确率、节省工时、生产收益或优于直接聊天的数字。

## 优惠券操作练习中的引用失败

后续以全新的“满100元减20元”资料进行真实操作，需求整理得到6项草稿。生成阶段两次因模型把不同段落拼接为同一个连续引用而失败；仅选“不足100元不能使用”一条需求后，模型仍额外提出了满100元及超过100元的场景，其中一条引用不连续，整批没有保存。期间还触发了工作台每日请求次数上限，不能将其写成模型服务余额不足。

据此加强所选需求约束，并增加一次有上限的校验反馈：提供已核验原文引用，要求模型重新提交完整草稿；没有把拼接引用直接当成真实原文。受控回归验证了修正成功、再次失败、未授权引用和总调用次数边界。修复后的新真实生成由后续操作验证，不能用受控响应代替成功证据。

## 逐字段复核的后续检查

单条不足100元规则后来真实生成1条草稿，金额判断正确，但仍增加了已选中优惠券、结算页和提示要求。随后加入独立上下文复核前置、数据、步骤和预期，以及人工确认后的固定数值计算。新流程使用同一模型的额外复核调用，并不是多个自主Agent互相保证正确。

构造两条新的检查用例，均用订单99.99元：一条采用通用尝试操作及不抵扣的预期，另一条加入必须登录、特定页面、红色弹窗、固定文案和79.99元预期。用例正文由人工构造；真实模型只承担复核，不计入用例生成质量。

第一次真实复核已指出后一条的风险，但将前一条前置中的99.99元归为测试数据，服务端因分类限制过严而拒绝整批。保留失败后，允许只描述构造对象与输入的前置条件使用测试数据分类，并要求关联适用规则；业务预期仍不可用此分类掩盖。再次检查通过了流程。

上述探索标题含有风险提示，因此另外将两个标题改为中性的“订单99.99元使用优惠券检查A／B”，不向复核输入提供正确／错误标签，再进行一次真实复核。返回A未发现疑点，B的前置、步骤及预期被标为无依据或冲突，输入金额被识别为构造数据。程序计算结果为不允许抵扣、应付99.99元。检查使用自编小样本，不能推断一般准确率；复核模型仍可能漏判或误判。

完整后端275项回归、边界调整后的关键68项和数值依据模块24项检查通过，前端16项及生产构建通过。覆盖数值来源、十进制边界、无效输入、项目范围、字段缺失、复核未完成时的草稿保存、显式人工确认、旧报告失效和历史执行关联；其中受控响应用于工程行为验证。
